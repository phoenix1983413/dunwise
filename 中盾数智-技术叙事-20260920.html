03

痛点：数据供给侧的两道硬墙

为什么通用路线走不通
Wall 01

过程不可观测

全域运行态缺乏统一时钟基准与统一语义模型，无法形成可回溯的过程级留痕。

后果模型只能看到"结果"，学不到"过程"；异常与博弈样本无从捕获。
Wall 02

语料不可获得

零样本、强监管、不可再生数据域；不满足公开语料迁移条件，亦不具备仿真合成的保真度。

后果训练数据永远缺位，模型能力被锁死在通用语料上限。
04

解法：五步构成一条数据生产线

不是造数据，是采集真实过程

以指挥者身份介入（Commander-in-the-loop）

不做旁观式埋点，而是以指挥视角贯通硬件协同链路与执法流程链路。

旁路无侵入采集

不改动既有系统、不影响生产链路，实现零侵入接入。

统一时空对齐

多源异构设备时戳归一，交互序列在统一时间轴上严格对齐。

语义归一化

以执法流程本体（Ontology）为基准做语义映射，跨厂商、跨型号数据口径一致。

业务同时刻落库

数据在业务发生的那一刻即完成结构化，标注天然生成——无需事后人工标注。

05

三大关键技术

TFA / UDA / MCP-Native
TFA 全域过程可回溯采集引擎 Traceable Full-process Agent
设计范式Event Sourcing（事件溯源）+ 旁路镜像。不记录"当前状态"，而记录"每一次变化"，因此过程可完整回放、可逐帧复现。
三统一统一时钟（多源异构设备时戳归一）、统一语义（执法流程本体建模 / Ontology）、统一血缘（数据血缘 Lineage 全链路可追溯、可审计）。
产出物不是日志，而是过程级轨迹（Trajectory）：每一次交互都是一条带上下文、带因果链、带结果反馈的可训练样本。
核心红利Process-as-Label（过程即标注）——标注在业务发生的那一刻天然生成，从根上解决公共安全领域"标注成本高于数据价值"的成本倒挂问题。
记住这一句别人产日志，我们产轨迹；别人事后标注，我们过程即标注。
UDA 统一数据计算底座 Unified Data Analytics
批流一体Unified Batch-Streaming：同一套 SQL / 算子逻辑同时覆盖历史批算与实时流算，消除 Lambda 架构"批流双链路口径不一致、需长期对账"的系统性缺陷。
弹性扩展万亿级规模 + 存算分离：数据规模跨数量级增长时算力按需伸缩，峰值负载不构成瓶颈。
双模开发Code + Canvas：既能写代码（Python / SQL / DAG 编排，面向算法团队），也能拖拽算子（可视化算子编排，面向业务与指挥人员），共用同一套执行引擎，开发效率与治理口径不分裂。
场景定制分析模型随场景灵活定制，算子可复用、可组合、可沉淀为行业算子库，新场景以"拼装"而非"从零开发"的方式交付。
记住这一句一个引擎，两套开发形态；新场景交付是拼装，不是开发。
MCP-Native Agent 原生接入 Model Context Protocol
标准暴露两大产品原生内置 MCP-Server：数据侧以工具（Tool）形态、处理侧以动作（Action）形态，按标准协议对外暴露。
零成本集成无需私有适配层，无集成成本，Agent 可直接接入、即插即用。
战略含义我们交付的不是"一个系统"，而是可被任意智能体编排的数据能力面与算力能力面——Agent 生态越繁荣，底座价值越高。
记住这一句别人的接口是私有的，我们原生 MCP，任何 Agent 即插即用。

术语弹药库

内部使用 · 被追问时的"人话解释"
术语人话解释想传递的信号
Event Sourcing不记"当前是什么样"，记"每一步怎么变的"，所以过程能完整回放。数据可复现，不是快照。
Process-as-Label标注是业务运行的自然产物，不是事后雇人打的。数据成本结构根本不同。
Trajectory一条完整"前因—动作—结果"记录，正好是大模型训练要的格式。直接对齐主流训练范式。
批流一体历史和实时用同一套代码算，口径只有一个。数据可信。
存算分离存储与算力分开买、分开扩。万亿级也撑得住。
本体建模 / Ontology先把业务的"概念与关系"定义清楚，数据才有统一含义。我们懂业务，不只是懂技术。
数据血缘 Lineage每个数字都能追到它是哪来的。强监管场景可审计。
MCP-Server让 AI 智能体即插即用地调用我们的数据与算力。不封闭，生态友好。
Double Ready数据集拿起来就能训，指令集拿起来就能跑。交付即生产力。
