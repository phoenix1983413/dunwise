# 发明专利申请文件 · 件二

## 一、发明名称

**一种轨迹数据的可回放封装与能力受控接入方法及系统**

---

## 二、说明书摘要

本发明公开一种轨迹数据的可回放封装与能力受控接入方法及系统，涉及数据处理技术领域。该方法接收包含按统一逻辑时钟排序的事件序列的过程轨迹数据，解析其中被引用的外部依赖并判定为纯函数依赖、状态依赖、副作用依赖或版本依赖，分别生成记录调用参数与返回值、记录状态取值与来源标识、生成桩定义、记录版本标识等处理约定；依据动作序列生成含任务描述、可用工具集与工具模式、期望动作序列与成功判定条件的指令条目；在隔离执行环境中按处理约定重建外部依赖并驱动执行，比对实际执行轨迹与期望动作序列得到可复现性度量；将数据访问能力与数据处理能力以工具形式注册至模型上下文协议服务端并关联能力契约；接收携带目的声明的调用请求，经契约匹配校验后按字段级掩码规则返回数据；最后将调用记录与校验结论以过程事件形式回写。本发明解决了轨迹数据因外部依赖状态变化而不可复现、以及敏感数据面向智能体开放时缺乏目的级与字段级访问控制的技术问题。

## 四、说明书

### 4.1 技术领域

本发明涉及数据处理技术领域，具体涉及一种轨迹数据的可回放封装与能力受控接入方法及系统。

### 4.2 背景技术

随着智能体（Agent）技术的发展，以真实过程数据训练与评测智能体成为一种需求。所述过程轨迹数据是指按时间顺序记录的、包含动作与状态变化的事件序列，其典型来源为设备协同过程、业务系统流程执行过程或者智能体自身的交互过程。

将过程轨迹数据用于智能体训练与评测时，存在以下障碍。

第一，轨迹数据在外部依赖状态变化后不可复现。轨迹数据仅记录动作与结果，而未记录执行该动作时所依赖的外部环境的取值。当外部依赖为可变的数据库记录、可变的设备状态或可变的配置项时，重新执行同一轨迹将得到不同结果，因而无法验证、无法回归测试，也无法作为训练样本被反复使用。

第二，轨迹数据不区分外部依赖的性质。轨迹数据所引用的外部依赖中，一部分是输出仅由输入决定的确定性依赖，另一部分是会产生不可逆外部效果的依赖（例如向设备下发控制指令、向业务系统写入记录）。若不区分即行回放，将产生不可控的副作用，甚至影响真实系统。

第三，敏感数据面向智能体开放时缺乏目的级与字段级访问控制。现有的模型上下文协议规定了智能体以客户端-服务端方式调用外部工具与资源的接口形式，但其仅规定接口形式，未提供在调用时校验调用目的、限制可访问字段粒度的机制。在此情况下，智能体可无差别读取工具所暴露的全部字段，无法满足敏感数据在最小必要与目的限定方面的要求。

第四，数据消费行为不产生可回写的过程事件。现有方案中，数据被智能体读取后，该读取行为不反馈至数据的生产侧，数据消费侧与数据生产侧之间不构成闭环，因而无法形成面向真实使用情况的数据迭代。

因此，如何解决轨迹数据因外部依赖状态变化而不可复现的技术问题，如何解决外部依赖不分性质即行回放而产生不可控副作用的技术问题，以及如何解决敏感数据面向智能体开放时缺乏目的级与字段级访问控制的技术问题，成为本领域亟待解决的技术问题。

### 4.3 发明内容

#### 4.3.1 本发明所要解决的技术问题

（1）过程轨迹数据仅记录动作与结果而未记录外部依赖的取值与版本，导致在外部依赖状态变化后轨迹不可复现的技术问题；

（2）过程轨迹数据不区分外部依赖的性质，回放时对会产生不可逆外部效果的依赖执行调用，从而产生不可控副作用的技术问题；

（3）敏感数据以工具形式面向智能体开放时，调用请求不携带使用目的、返回数据不受字段级约束，导致无法实施目的限定与最小必要控制的技术问题；

（4）数据消费行为不产生回写事件，导致数据生产侧无法获得使用侧反馈的技术问题。

#### 4.3.2 技术方案

为解决上述技术问题，本发明提供一种轨迹数据的可回放封装与能力受控接入方法，包括步骤S1至步骤S6。

**步骤S1，接收过程轨迹数据并解析外部依赖。**

接收的过程轨迹数据包含按统一逻辑时钟排序的事件序列。所述事件序列中的每一条事件至少包含时间戳、主体标识、动作标识与动作参数；所述动作参数中可能引用外部依赖，例如数据库查询、设备状态读取、模型服务调用、配置项读取等。

解析事件序列中被引用的全部外部依赖，为每一个外部依赖判定依赖类别并生成对应的处理约定。所述依赖类别包含四类：

其一为纯函数依赖，其输出仅由输入参数决定，与调用时刻的外部状态无关。判定方式为：对该外部依赖的调用记录执行相同输入下的重复调用测试，当重复调用的输出一致时判定为纯函数依赖。其处理约定为记录该次调用的调用参数与返回值，回放时以查表方式直接返回记录值，不再实际发起调用。

其二为状态依赖，其输出依赖于外部可变状态。判定方式为：重复调用的输出不一致，且输出与外部存储中的取值相关。其处理约定为记录状态取值以及状态来源标识，回放时依据状态来源标识重建该状态。

其三为副作用依赖，其调用会产生不可逆的外部效果，例如向设备下发控制指令、向业务系统写入记录、发送通知等。判定方式为：该外部依赖的调用记录中包含写入、下发或者控制类操作。其处理约定为生成桩定义，所述桩定义包含方法签名、返回约束与副作用拦截规则；回放时加载该桩替代真实依赖，从而在保留调用形态的同时拦截副作用。

其四为版本依赖，其输出随模型版本、提示词版本或配置版本发生变化。其处理约定为记录版本标识，并在回放时强制版本一致；当回放环境的版本与记录版本不一致时，终止回放并输出差异提示。

**步骤S2，生成指令条目。**

依据事件序列中的动作序列生成指令条目。每一条指令条目包含：任务描述，采用自然语言表述该动作序列所要完成的任务；可用工具集及其工具模式，用于界定执行该任务时可调用的工具范围；期望动作序列，为应当执行的动作的有序列表；成功判定条件，为可自动校验的条件表达式。

在一个优选的实施方式中，对于已经标注为偏离类型的轨迹，本发明进一步生成该轨迹所对应的正确动作序列，即该轨迹在过程模型下应当执行的动作序列，并将偏离轨迹作为偏好对的被拒样本、将正确动作序列作为偏好对的选取样本，构成偏好对样本。由此，同一份过程数据可同时用于监督微调与偏好学习。

**步骤S3，隔离环境回放与可复现性度量。**

在隔离执行环境中，首先按照步骤S1生成的各处理约定重建外部依赖：对纯函数依赖按记录值查表返回；对状态依赖按状态来源标识重建状态；对副作用依赖加载桩定义；对版本依赖锁定版本。随后按照指令条目驱动执行，并将实际执行轨迹与指令条目中的期望动作序列进行比对，得到可复现性度量。

所述可复现性度量包含下述一项或多项的加权组合：动作序列匹配率，即实际执行的动作序列与期望动作序列的一致比例；参数一致率，即动作参数的一致比例；判定结果一致率，即成功判定条件求值结果的一致比例。

当可复现性度量小于预设可复现阈值时，将该事件序列所对应的样本标记为不可复现样本，并对其执行剔除处理或者降低其样本权重。由此，数据集在封装阶段即完成了自检，只有可复现的样本才进入下游使用。

**步骤S4，能力契约注册。**

将数据访问能力与数据处理能力以工具形式注册至模型上下文协议服务端。所述数据访问能力例如为按条件查询轨迹、读取指定轨迹的载荷、读取指定流程实例的全部事件等；所述数据处理能力例如为执行一致性比对、生成训练样本、统计异常过程模式等。

注册时，为每一个工具关联一份能力契约。所述能力契约包含：允许调用的主体标识，用于限定可调用该工具的主体；资源范围，用于限定可访问的数据范围，例如数据集标识、轨迹标识范围或时间范围；字段级掩码规则，用于限定返回数据中各字段的脱敏方式；允许的使用目的，采用枚举方式列出该工具所服务的目的。

**步骤S5，调用意图校验。**

接收调用请求。所述调用请求除包含工具标识与调用参数之外，还必须包含目的声明。校验过程包含下列各项：

目的匹配，将调用请求中的目的声明与能力契约中允许的使用目的进行匹配，不匹配则判定校验不通过；

主体校验，校验调用主体标识是否在允许调用的主体标识范围之内；

资源范围校验，确定调用请求所指向的数据范围，当该数据范围超出能力契约中的资源范围时，按照最小可用原则对返回数据进行裁剪，或者当两者不存在交集时判定校验不通过；

掩码施加，按照字段级掩码规则对返回数据施加掩码后返回；

频次控制，统计该主体在预设时间窗内的调用次数，当超过能力契约中的调用频次上限时判定校验不通过。

校验通过后返回经掩码处理的数据；校验不通过时拒绝该调用请求，并返回结构化拒绝原因。所述结构化拒绝原因包含请求主体标识、请求所指向的工具标识、未通过的校验项标识与拒绝时间戳，并同时被写入审计事件。

需要说明的是，模型上下文协议本身解决的是"如何调用"的问题，即接口的形式与传输方式；本发明所解决的是"是否应当提供、提供至何种字段粒度、服务于何种目的"的问题。二者处于不同的技术层次，本发明在协议之上增加了基于目的声明的授权判定。

**步骤S6，审计回写。**

将调用请求、校验结论以及返回数据摘要以过程事件形式回写至过程轨迹数据。回写所得的过程事件使数据消费行为本身也被记录为一条可观测的轨迹，据此可生成监督样本，用于表征调用主体的数据使用行为是否符合能力契约。

由此，本发明形成了从数据生产到数据消费再回到数据生产的闭环：采集产生的轨迹被封装为可执行的数据集；数据集与处理能力经能力契约受控开放；消费行为回写成为新的过程事件；新的过程事件又可参与后续的样本生成。

#### 4.3.3 有益效果

（1）解决了轨迹数据不可复现的技术问题。通过对外部依赖分类并生成版本化引用与桩定义，使数据集自带可重建的执行环境，在外部依赖状态变化后仍可复现。

（2）解决了回放产生不可控副作用的技术问题。通过对副作用依赖强制生成桩定义并拦截副作用，使回放可在不接触真实系统的前提下完成。

（3）解决了敏感数据开放缺乏目的级与字段级控制的技术问题。通过目的声明与能力契约的匹配校验以及字段级掩码规则，实现目的限定与最小必要控制。

（4）解决了数据消费行为无法反馈至生产侧的技术问题。通过审计回写形成过程事件，使消费行为可被追溯并可转化为监督样本。

（5）提升了数据集的可信度。通过在封装阶段输出可复现性度量并剔除不可复现样本，避免不可复现样本进入下游使用。

#### 实施例一

本实施例以对执法过程轨迹数据进行可回放封装为例。

**一、轨迹接收与外部依赖解析**

轨迹接收与依赖解析模块20接收过程轨迹数据。所述过程轨迹数据包含按统一逻辑时钟排序的事件序列。本实施例中一条轨迹的事件序列如下（节选）：

| 序号 | 时间戳（统一逻辑时钟） | 主体 | 动作 | 动作参数 |
|---|---|---|---|---|
| 1 | 09:12:30.603 | DEV-A | 开启录像 | 设备编号、分辨率 |
| 2 | 09:12:31.102 | 接处警平台 | 查询警情详情 | 警情编号 |
| 3 | 09:12:31.480 | 车载终端 | 读取当前位置 | 设备编号 |
| 4 | 09:13:02.771 | 指挥中心 | 下发调度指令 | 指令编号、目标单位 |
| 5 | 09:13:05.220 | 大模型服务 | 生成处置建议 | 提示词标识、上下文摘要 |

依赖识别单元21扫描动作参数，识别出下列外部依赖：序号2引用的警情详情查询接口、序号3引用的定位服务、序号4引用的指令下发接口、序号5引用的大模型推理服务与提示词模板。

依赖分类单元22逐一判定其依赖类别：

对警情详情查询接口执行相同输入的重复调用测试，两次输出一致，判定为纯函数依赖。

对定位服务执行相同输入（同一设备编号）的重复调用测试，两次输出不一致，且输出与设备当前位置这一外部可变状态相关，判定为状态依赖。

对指令下发接口，其调用记录中包含下发操作，会产生不可逆的外部效果，判定为副作用依赖。

对大模型推理服务，其输出随模型版本与提示词版本变化，判定为版本依赖。

处理约定生成单元23生成对应处理约定：

| 外部依赖 | 依赖类别 | 处理约定 |
|---|---|---|
| 警情详情查询接口 | 纯函数依赖 | 记录调用参数（警情编号）与返回值，回放时查表返回 |
| 定位服务 | 状态依赖 | 记录状态取值与状态来源标识（设备编号 + 采集时刻），回放时按来源标识重建 |
| 指令下发接口 | 副作用依赖 | 生成桩定义：方法签名 `sendDispatch(cmdId, targetUnit)`；返回约束为固定成功结构；副作用拦截规则为不进行实际下发，仅记录调用 |
| 大模型推理服务 | 版本依赖 | 记录模型版本标识 M-2026.03 与提示词版本标识 P-v7，回放时强制一致 |

**二、指令集生成**

指令集生成模块30生成指令条目，其结构如下：

```json

  "task": "在接收到警情派单后，按规范完成现场处置前的准备动作",
  "available_tools": [
    {"name": "query_alert_detail", "schema": "{...}"},
    {"name": "read_device_location", "schema": "{...}"},
    {"name": "send_dispatch_cmd", "schema": "{...}"}

  "expected_actions": ["开启录像", "查询警情详情", "读取当前位置", "下发调度指令"],
  "success_predicate": "all(expected_actions, executed) and no(unauthorized_tool_call)"
}
```

在另一情形下，若该轨迹被标注为偏离类型（例如缺失"下发调度指令"这一步），指令条目生成单元31生成其正确动作序列 `["开启录像", "查询警情详情", "读取当前位置", "下发调度指令"]`，偏好对构造单元32将原偏离轨迹作为被拒样本、将正确动作序列作为选取样本，构成偏好对：

```json

  "rejected": ["开启录像", "查询警情详情", "读取当前位置"]

```

**三、隔离环境回放与可复现性度量**

依赖重建单元41在隔离执行环境中重建外部依赖：警情详情查询接口按记录值查表返回；定位服务依据状态来源标识重建为该采集时刻的取值；指令下发接口加载桩定义，其调用被拦截且不产生实际下发；大模型推理服务锁定模型版本 M-2026.03 与提示词版本 P-v7。

执行驱动单元42按指令条目驱动执行，可复现性度量单元43将实际执行轨迹与期望动作序列比对，得到：

| 度量项 | 取值 |
|---|---|
| 动作序列匹配率 | 4/4 = 100% |
| 参数一致率 | 4/4 = 100% |
| 判定结果一致率 | 1/1 = 100% |
| 加权可复现性度量 | 1.00 |

预设可复现阈值为0.85。本例中可复现性度量1.00大于阈值，该样本被标记为可复现样本。

另一条轨迹因引用的定位服务在采集时刻未记录状态来源标识，回放时无法重建状态，其可复现性度量计算为0.62，小于阈值0.85，该样本被标记为不可复现样本并将其样本权重由1.0降至0.3。

**四、能力契约注册**

能力注册模块50将数据访问能力与数据处理能力以工具形式注册至模型上下文协议服务端80。工具注册单元51注册的工具包括 `query_trajectory`、`read_trajectory_payload`、`run_conformance_check`、`generate_sample`。

契约绑定单元52为各工具绑定能力契约。以 `read_trajectory_payload` 为例，其能力契约如下：

| 契约字段 | 取值 |
|---|---|
| 允许调用的主体标识 | AGENT-AUDIT-01、AGENT-TRAIN-02 |
| 资源范围 | 数据集 DS-2026Q1，时间范围 2026-01-01 至 2026-03-31 |

**五、调用意图校验**

意图校验模块60接收来自智能体90的调用请求。以一次调用为例，请求内容为：


目的匹配单元61将目的声明"过程审计"与契约中允许的使用目的比对，命中，通过。主体校验单元62校验主体标识 AGENT-AUDIT-01 在允许列表内，通过。范围校验单元63确定 requested 的轨迹 T-2026-0311-00187 落在数据集 DS-2026Q1 与时间范围内，通过。掩码施加单元64按字段级掩码规则处理返回数据：

该结构化拒绝原因同时由审计回写模块70写入审计事件。

**六、审计回写**

审计回写模块70将调用请求、校验结论与返回数据摘要以过程事件形式回写至过程轨迹数据：

```json
{
  "event_type": "tool_invocation",
  "t_unified": "2026-03-12T10:19:53.402",
  "subject": "AGENT-AUDIT-01",
  "tool": "read_trajectory_payload",
  "purpose": "过程审计",
  "check_result": "PASS",
  "masked_fields": ["device_serial", "person_name", "geo"],
  "response_digest": "sha256:9f2c…"
}
```

回写所得的过程事件构成新的轨迹。可据此生成监督样本，例如某主体在未声明正当目的的情况下反复尝试调用某工具，则该行为模式本身可被标记为异常并用于训练调用行为审计模型。

#### 实施例二

本实施例说明外部依赖分类判定的具体流程，其流程如图2所示。对每一个待判定的外部依赖，依次执行：

第一步，检查其调用记录中是否包含写入、下发或者控制类操作；若是，判定为副作用依赖，生成桩定义并结束；若否，进入第二步。

第二步，执行相同输入下的重复调用测试；若两次调用输出一致，判定为纯函数依赖，记录调用参数与返回值并结束；若输出不一致，进入第三步。

第三步，检查输出是否与外部存储中的取值相关；若是，判定为状态依赖，记录状态取值与状态来源标识并结束；若否，进入第四步。

第四步，检查输出是否随模型版本、提示词版本或配置版本变化；若是，判定为版本依赖，记录版本标识；若否，判定为不可分类依赖，并按照最保守策略处理，即按副作用依赖生成桩定义。

上述判定顺序将副作用依赖置于首位，其原因在于：副作用一旦发生即不可逆，故应优先识别并拦截，避免后续判定耗时期间已产生实际副作用。
